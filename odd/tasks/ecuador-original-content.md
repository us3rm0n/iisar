# Feature: ecuador-original-content

## Objective

Replace the verbatim book transcription in `content/geografia-ecuador.md` with ORIGINAL editorial content for the 24 province pages, using the book only as a guide for facts. Goal: legal safety and AdSense-eligible original content.

## Problem / Why

- `content/geografia-ecuador.md` (230 KB) is a word-for-word transcription of pages 63-132 of a third-party book, rendered live at `/ecuador/<provincia>` (24 pages). License unknown.
- AdSense requires original, high-quality content; copied text is a typical rejection reason.
- Facts are not protected, wording is: a rewrite must be new text, not a paraphrase or word-swap.

## Method (decision 2026-10-02, user: "rescribe usando como guia")

1. Fact extraction: one agent per batch reads the source lesson and writes a FACT SHEET (atomic facts, no copied sentences) to the session scratchpad, outside the repo.
2. Writing: a DIFFERENT agent receives ONLY the fact sheet (never the book) and writes the original article in its own structure.
3. Objective check: a script measures word n-gram overlap against the source (read from git history, so it still works after the file is removed from the tree). Proper-name-only sequences are ignored.
4. Human review of facts before publishing (a school text may be dated; avoid volatile figures such as population).

## Decision: editable from the frontend (user, 2026-10-02, mid-turn: "eso tambien quisiera poder editarlo desde en frontend")

- A build-time `.md` file cannot be edited from the browser, so the province content moves to Supabase: new table (province FK, markdown body, `updated_at`, `updated_by`), RLS public read and write only for the webmaster role (`is_webmaster()`, as for `categories`).
- Defaults chosen without asking (revisable): only the webmaster edits (editorial content, not owner content); editor = markdown textarea with live preview (minimalist, no rich-text dependency).
- The rewritten articles are produced as versioned drafts `content/provincias/<slug>.md` (reviewable in git diff) and loaded into the table by a generated migration; after that the UI is the source of truth.
- Security consequences: HTML coming from the DB is no longer trusted repo content, so rendering must sanitize before `{@html}` (must work on the Cloudflare Workers runtime: verify with `pnpm build`); `/admin` currently renders for logged-out visitors (pre-existing), so a server-side/guard fix is a prerequisite, with RLS as the real protection.
- The originality script only covers the initial rewrite; later UI edits are the user's responsibility.

## Facts from the mapping (2026-10-02)

- Only province page bodies are rendered (`ecuador/[provincia]/+page.svelte:44-47`, `{@html}`, trusted content). Region and general lesson bodies are not rendered; the index page shows general lesson titles only.
- Loader: `src/lib/content/ecuador.server.ts:8-13` globs `/content/*.md`, reads `geografia-ecuador.md`; missing file gives empty content. Parser: `src/lib/content/ecuador.ts` (`## ` split; title regex `Lección N — Name` or raw title; slug = `slugify(title)`; region keywords in titles route to `regions`; `regions.insular` is aliased to `provincias.galapagos`).
- Join key with DB: slug of the title must equal the seeded `provincias.slug` (24 provinces; migration `20250831000005_provincias.sql`). Keep titles such as `Los Ríos`, `Santo Domingo de los Tsáchilas`, `Zamora Chinchipe`; Galápagos needs a heading containing "Galápagos".
- Tests use fixtures, not the real file: replacing content breaks no test. No `scripts/` dir exists.
- `.prose-content` styles h3, p, ul, ol, strong, `.table-scroll`, table; h4 and blockquote are not styled.
- Remote `origin` is `git@github.com:us3rm0n/iisar.git` (possibly public): the transcription stays in git history after the rewrite. Purging history is destructive and is the user's decision (not started).

## Constraints

- UI copy and the content are Spanish (existing project language); code, comments and identifiers English.
- No verbatim or close paraphrase of the source; no invented facts: use only the fact sheet; flag gaps instead of filling them.
- Strict TDD (runner `pnpm test`). Pure logic gets a RED spec first. Markdown content is checked by the originality script and the build.
- Never run `pnpm format` repo-wide; prettier baseline is 3 files (`content/geografia-ecuador.md`, `src/lib/supabase/helpers.ts`, `src/lib/utils/date.ts`).
- No push, PR or merge: user decisions. Planning heuristic ~400 changed lines per task, advisory only.
